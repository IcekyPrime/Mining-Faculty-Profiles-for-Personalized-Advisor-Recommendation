# 底层审查与数据挖掘改进

> 审查对象：`Mining-Faculty-Profiles-for-Personalized-Advisor-Recommendation-副本`（本地改进版，v2.7.0）
> 审查时间：2026-11-24
> 范围：AI 配置与本地端点、BM25/检索召回、对话缓存、导入与审计、数据质量、公开项目对照
> 原则：只新增、不删除；不改 `score/score2` 权重口径；本轮只更新处理层派生列，不重建教师/论文/课程数据。

## 1. 结论摘要

本轮先复现、再修复，第一轮修复 **15 类可复现问题**，新增 **8 项回归测试**，全量测试从 98 项增至 106 项；
第二轮在不扩充数据的前提下增加缩写扩展与 Graph RAG 合作者召回；第三轮把查询扩展、主题模型、
聚类和关联规则改成可配置/语料自学习组件，当前 **115 项通过**。

最值得先做的不是继续调权重，而是在**不能扩数据**的前提下把现有算法通用化、并固定评估口径：

1. **通用挖掘组件**：主题模型、自动 K 聚类、动态项集、外置词典与语料自学习（第三轮已完成）。
2. **可比较的评估集**：现有 10 条查询、二元标签，规则 0.959、BM25F 0.794、混合 0.809；
   需要扩到 50 条、0/1/2 分级、双人标注与显著性检验，才能判断提升是否稳定。
3. **数据补全**：实体消歧（DBLP/OpenAlex/ORCID）与 DOI/会议/年份补全需要外部数据；
   在“数据无法继续扩充”的约束下不把它作为本轮交付，只保留为后续选项。

### 4.1 对照后的判断

- **不是缺一个“更强的模型”**：本项目 BM25F 在自建 10 条查询上 0.794，规则相关度 0.959，但标签是按研究方向完整串人工核对的，规则天然占优；这与公开论文的 0/1/2 分级标签不可直接比较。
- **最短板是数据而不是排序器**：DOI/venue/年份缺失、作者未消歧、paper_count 双口径，会同时影响相似度、主题模型、评分和解释。
- **语义检索应做“晚融合”而不是“把摘要拼进主页”**：公开论文明确报告拼接 arXiv 摘要使 NDCG 降 0.176；应分别编码主页/论文，再做 RRF 或加权融合。
- **个性化应做“可编辑兴趣画像”**：Grapevine 的核心不是图数据库本身，而是学生能看见并调整兴趣词，系统实时解释为什么推荐。

## 5. 改进清单（按投入产出排序）

### P0 · 先补数据底座（1–2 周，风险低）

1. **教师稳定 ID 与实体消歧**
   - 新增字段：`dblp_id`、`openalex_id`、`orcid`、`google_scholar_id`、`homepage_url`（保留现有字段，不删）。
   - 先人工确认 4 组同名教师，特别是同学院“赵阳”两条；其余 3 组用学院+主页+论文标题消歧。
   - 导入接口增加“教师 ID 优先，姓名+学院次之，同名多候选必须报错”的规则（本轮已完成后半段）。
   - 验收：4 组全部有结论；导入不再出现“按姓名挂错人”；新增 `(source, source_id)` 唯一约束。

2. **论文元数据补全与去重**
   - 用 OpenAlex/Crossref 按标题+作者+年份匹配，补 DOI、venue、year、citation；DOI 统一小写、去 `https://doi.org/` 前缀。
   - 以 DOI 为第一去重键，标题规范化+年份为兜底；保留 `source`、`fetched_at`、`confidence`。
   - 验收：DOI 覆盖率从 18.0% 提到 ≥80%；venue 覆盖 ≥70%；重复论文不增加；补全可回滚。

3. **统一 `paper_count` 口径**
   - 明确“学术页声称的论文数”和“本地可检索论文行数”是两个字段，不要互相覆盖。
   - 评分/展示用“本地已收录 N 篇（学术页 M 篇）”；新增一致性测试，目标差异从 231/204 降到 <5%。
   - 验收：`data_quality_report.py` 中两个异常指标进入 CI 阈值；`score_v2` 仍用原权重，只换数据源。

4. **评估集升级**
   - 从 10 条扩到 50 条，覆盖跨学院、跨方向、冷门方向、姓名/拼音、多词查询。
   - 标签改 0/1/2 分级；至少 2 人标注，报告 Cohen's κ 或 Krippendorff's α。
   - 指标：NDCG@10、MAP@10、P@5、HitRate@10；paired bootstrap 95% CI + Bonferroni。
   - 验收：规则、BM25、dense、hybrid、rerank 在同一批标签上可比；不再用“规则 0.959 vs BM25 0.794”直接下结论。

### P1 · 检索与画像（2–4 周）

5. **BM25 + dense + RRF 混合召回**
   - 先对“主页简介 + 研究方向 + 关键词”做 BGE-M3/MiniLM embedding；论文摘要单独建向量，不要拼进主页。
   - BM25 与 dense 各取 top 50，RRF 融合，再用 cross-encoder 重排 top 20；无模型时自动回退 BM25。
   - 参考公开结果：Reranked 0.477 > Semantic 0.450 > Hybrid 0.421 > BM25 0.406（同一 768 人/5 查询基准）。
   - 验收：同一评估集 NDCG@10 相对 BM25 提升 ≥10%；P95 延迟 <300 ms（本地缓存命中时）。

6. **简介单独建通道，不拼摘要**
   - 当前 BM25 字段没有 `bio`；609/773 有简介。公开论文显示 biography 单字段最强。
   - 先做字段消融：`bio` 单独、`bio+方向`、`bio+关键词`、全字段；截断长简介，避免职业生涯段落稀释。
   - 验收：字段消融有表格；若 `bio` 通道无增益则不启用，不凭直觉上线。

7. **可编辑学生兴趣画像**
   - 新增 `student_profile`：兴趣词、方向权重、偏好学院/职称/城市、是否读博、时间预算。
   - 推荐结果给出“命中哪些兴趣词/论文/主题”，支持增删关键词后实时重排；收藏/对比作为弱反馈。
   - 参考 Grapevine 的 open user model；先不做复杂 GNN，先把“可解释+可控制”做出来。
   - 验收：同一查询下用户调整 1 个关键词，top 10 变化可解释；推荐理由引用具体证据。

8. **导师招生状态与时效**
   - 结构化字段：`advising_status`（招生中/待确认/不招生/未知）、`status_source`、`status_date`、`confidence`。
   - 只从主页/实验室/招生页抽取，LLM 仅做辅助，不允许无来源生成；超过 90 天标“待核验”。
   - 验收：每条状态可点回源 URL；未知不显示为“不招生”。

9. **公平性与多样性**
   - 统计学院、职称、性别（如有）、长尾方向的曝光占比；用 Gini/Entropy、ILD、覆盖率。
   - 排序加 MMR 多样性重排，避免 top 10 全是同一学院/同一主题。
   - 验收：评估报告固定输出 exposure 表；不以“降低相关性”换多样性，需给出相关性损失。

### P2 · 结构化与规模化（1–2 个月）

10. **主题模型升级**
    - 当前 `KMeans K=8` + 关键词；可换 BERTopic/SciBERT 或 OpenAlex topic 作为弱标签。
    - 主题层级用 domain/field/subfield/topic；教师按主题克隆，处理“高产作者主导聚类”。
    - 相似度用主题分布 JSD/ cosine，保留 MinHash 作为可解释基线。
    - 验收：silhouette、主题一致性人工抽检、下游 NDCG 三项同时报告。

11. **合作网络扩展**
    - 当前 PageRank/HITS 只覆盖 127/773；先用 OpenAlex coauthorships 扩展到全部学院。
    - 再考虑 heterogeneous graph（教师-论文-机构-主题）与 metapath2vec/GNN；数据覆盖不足时不上 GNN。
    - 注意 `assistant/rag.py` 目前只对已有 lexical 命中做邻居加权，不会新增邻居候选；“找合作者”类查询需要单独召回通道。

12. **增量 ETL 与可观测性**
    - 采集/补全/评分拆成可重跑步骤，记录 `source`、`fetched_at`、`run_id`、`row_count`、`error_count`。
    - 数据契约：DOI 格式、年份范围、教师外键、同名多候选、paper_count 一致性；异常进入告警而不是静默通过。
    - 移动端 `data.js` 与数据库做版本号/哈希校验，避免 13,092 与 13,088 的静态数据漂移。

13. **安全与稳定性加固**
    - `fetch_page_text()` 已关闭流式响应；`_host_is_public()` 仍是“先 DNS 再 requests 再解析”的 TOCTOU 模式，建议解析一次后绑定 IP 或使用代理白名单。
    - 对 AI 输出做 JSON schema 校验与引用校验；补全任务保留 before/after 和备份，禁止无来源覆盖。
    - 真实云端 API、Ollama 生成、Android APK 构建仍未实测，发布前补一轮端到端。

## 6. 建议的下一轮验收顺序

1. 先做 P0-1/P0-3：实体消歧 + paper_count 统一，补测试，不动权重。
2. 再做 P0-4：50 条分级评估集；没有它，P1 的 hybrid 提升无法证明。
3. 然后 P1-5/P1-6：dense + RRF + bio 消融，按同一评估集对比。
4. 最后 P1-7/P1-8：学生画像与招生状态；这两项决定产品体验，不决定离线指标。
5. P2 的主题/图模型在 DOI 与作者 ID 补齐后再做，否则是在噪声上做复杂模型。

## 7. 第二轮：不扩充数据的检索增强（2026-11-24）

在数据量无法继续增加的前提下，只使用现有 773 位教师、13,088 篇论文、1,663 条课程记录做算法侧改进。

### 7.1 已落地

| 改动 | 文件 | 说明 |
|---|---|---|
| 查询缩写扩展 | `app/retrieval.py`、`data/mining/lexicon.json` | 缩写与中文写法改为外置词典；同时从当前语料的“中文（英文缩写）”写法自动学习，换学科/换数据后不需要改代码 |
| 对话姓名索引 | `assistant/rag.py` | 增加 `name` 字段与 4.0 字段权重；问“朱燕民”不再依赖方向/关键词碰运气 |
| Graph RAG 合作者召回 | `assistant/rag.py` | 普通查询只给已有词法命中的合作者加权；明确问“合作者/团队/实验室”时，从种子教师沿合作边新增最多 2 个高权重邻居，并写入 `graph_reason` |
| 移动端缩写扩展 | `mobile/android/assets/www/js/mobile-ai.js` | `ML/CV/NLP/LLM/GNN/FL` 等加入现有 alias 表；短英文按词边界匹配，避免 `html` 命中 `ml` |
| 回归测试 | `tests/test_retrieval.py`、`tests/test_api.py`、`tests/test_chat_api.py`、`tests/test_mobile_assets.py` | 缩写扩展、`ML` 查询、Graph RAG 合作者、移动端 alias 接线各一条 |

### 7.2 做了但回退的实验

| 实验 | 结果 | 结论 |
|---|---|---|
| 把现有 `bio` 以 0.8 权重加入 BM25F | 10 条查询平均 NDCG@10 从 0.794 **降到 0.668** | 现有中文简介夹带任职/项目/学院词，噪声大于研究信号；**已回退**，简介继续只在对话 RAG 中使用 |
| 中文同义词全量扩展（计算机视觉→图像处理、机器人→具身智能等） | NDCG 从 0.794 **降到 0.682** | 泛化词拉进主题更散的档案；只保留低歧义的“缩写→标准写法”扩展 |

这两次负结果说明：**“用了更多字段”不等于“检索更好”**；在现有标签口径下，字段噪声和查询漂移会直接抵消收益。

但 `ML`、`CV` 这类此前无法召回中文档案的查询现在可以命中。Graph RAG 的“朱燕民 合作者”查询

## 8. 第三轮：可泛化的数据挖掘流水线（2026-11-24）

这一轮不再增加任何教师、论文或外部 ID，目标是把“只对当前 773 人有效”的规则改成
**换一批数据也能运行的算法组件**，并让课程中的主题模型、降维、聚类、关联规则和评估
在应用里直接可见。

### 8.1 新增通用组件

| 组件 | 文件 | 课程知识点 | 泛化点 |
|---|---|---|---|
| 外置领域词典 | `data/mining/lexicon.json` | 特征/领域知识 | `aliases` 与 `areas` 可替换，不改代码 |
| 语料自学习缩写 | `app/mining.py` | 文本预处理、模式抽取 | 从“中文（英文缩写）”自动学习，小语料阈值自动放宽 |
| 主题模型 | `processing/topic_model.py`、`app/mining.py` | TF-IDF、NMF、主题分布 | 主题数由语料规模与轮廓系数决定，输出教师-主题分布 |
| 主题检索 | `app/api.py` | 向量空间、余弦相似度、混合检索 | `sort=topic` 在 BM25 召回集内融合主题分数，不改变其它排序 |
| 自动聚类 | `processing/clustering.py` | SVD 降维 + K-means + 轮廓系数 | K 不再写死为 8，聚类前先做 TruncatedSVD |
| 动态关联规则 | `processing/association.py` | Apriori、支持度/置信度/提升度 | 项集优先读词典，缺失时从当前语料 TF-IDF 高频词自动生成 |
| 对话 RAG 扩展 | `assistant/rag.py` | 词法检索、同义词扩展 | 词典与语料自学习缩写同时服务对话检索 |

### 8.2 评估结果（10 条人工标注查询）

| 方法 | NDCG@10 | MAP@10 | P@5 |
|---|---:|---:|---:|
| 规则相关度 | 0.954 | 0.925 | 0.920 |
| BM25F | 0.768 | 0.673 | 0.680 |
| 纯主题模型 | 0.097 | 0.050 | 0.080 |
| BM25 + 主题（0.6/0.4） | **0.798** | **0.703** | 0.660 |

纯主题模型是粗粒度画像，单独排序会丢失词法证据，因此只作为诊断；应用里的
`sort=topic` 采用 BM25 召回集内融合。相比 BM25F，NDCG@10 提升 0.015、MAP@10 提升 0.011，
P@5 持平。这个提升幅度不大，但方向与“先保证词法召回、再用主题做重排”的预期一致。

### 8.3 泛化边界

- 主题模型只使用研究方向/研究主题/简介的前 360 字，不依赖固定教师 ID；
- 聚类与关联规则都从当前数据库的文本列生成，换学校/学院后重跑即可；
- 主题检索是“主题词投影 + 教师主题分布余弦”，不要求保存 sklearn 模型对象；
- 仍然是**领域相关**的：中英文混合分词、教师字段语义、课程标签口径需要在新数据上重标；
  这不是“任意表格零配置”，但已从“写死当前数据”推进到“配置 + 语料自学习”。
