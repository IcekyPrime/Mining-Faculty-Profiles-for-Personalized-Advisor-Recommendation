## 3. 数据口径提醒

两边数据库不是同一份快照：

- 合并副本：773 教师 / 13,088 论文 / 1,663 课程；`processing` 有 `score_v2`、`score_coverage`、`score_parts`；
- GitHub v1.9：773 教师 / 11,093 论文 / 1,663 课程；`processing` 有 `teaching_imputed`。

本副本**没有**用 v1.9 的库覆盖现有库，避免丢失 v2 评分与 2,000 篇论文记录。
如果需要统一口径，应先跑 `run_pipeline.py` 重新采集，再跑处理层，而不是直接复制 `mentor.db`。

## 4. GitHub 版没有模型清洗

GitHub `e0bbf71` / `v1.9` 的 `app/` 只有 `__init__.py` 和单体 `app.py`，路由只有统计、检索、
教师、学院、洞察；没有 `/api/import`、`/workspace`、OpenAI/Qwen/Ollama 客户端，也没有
`import_*.py`。它的清洗是 `processing/preprocess.py` 的规则处理：正则、拼音索引、作者抽取、
年份修复、合作网络，不是模型清洗。

本副本的模型清洗是数据工坊的可选扩展：`app/import_ai.py` 可调用 OpenAI 兼容 API 或本机
Ollama/Qwen 复核字段；默认仍走规则清洗，模型不生成缺失事实。
