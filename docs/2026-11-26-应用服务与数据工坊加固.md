# 2026-11-26 应用服务与数据工坊加固

## 这轮修了什么

### 1. 数据工坊的“设置消失”

问题复现：在首页打开设置，点“数据工坊”后进入 `/workspace`，页面没有设置入口；再点设置也没有抽屉。原因是首页和数据工坊各自维护页面，设置抽屉只写在 `index.html`。

处理：

- 把设置抽屉抽成 `app/templates/_settings_drawer.html`，首页和数据工坊共用；
- 数据工坊顶栏加入“设置”按钮，补齐 `app-shell.css`、`app-shell.js`、`ai-settings.js`；
- 设置里的“数据工坊”在工坊页显示为“当前页面”，避免误以为链接失效；
- 设置入口保留 `aria-haspopup`、`aria-controls`、`aria-expanded`，关闭时恢复原来的焦点。

### 2. 设置抽屉的交互细节

参考成熟 Web 应用常见的 dialog 行为：

- 打开时聚焦关闭按钮，Tab 在抽屉内循环，Escape 关闭，点击遮罩关闭；
- 关闭后焦点回到打开按钮；
- AI 配置有未保存修改时，关闭前二次确认；离开页面前由 `beforeunload` 拦截；
- 保存/测试期间按钮禁用并设置 `aria-busy`，避免重复提交；
- 前端校验 API Base、模型名、模型 Key、搜索 Key、结果数；
- 错误字段加 `is-invalid` 样式，不再只在一个角落显示一条状态；
- 增加“有未保存修改”状态提示。

### 3. 数据工坊任务状态

- 预览成功后把 token 写回 URL：`/workspace?job=<token>`；
- 刷新、复制链接、从历史记录进入都能恢复同一份预览与处理层状态；
- 处理层中断后显示 `failed` 与具体原因，不再只显示一个没有说明的步骤条；
- 预览报告头部增加任务状态标签（预览中/写入中/已入库/失败）。

后端：

- 服务启动时把遗留的 `queued/running` 处理层任务标记为 `failed`，避免永久卡在 running；
- 写入任务元数据失败时删除已生成的预览行文件，避免孤儿文件；
- 处理层单步超时改由 `PIPELINE_TIMEOUT` 控制，默认 300 秒。

### 4. 应用服务配置与 HTTP 细节

- 所有路径配置支持环境变量：数据库、AI 配置、导入目录、备份目录、合作边、相似度文件、词典、主题文件；
- 增加 `MENTOR_MAX_UPLOAD_BYTES`、`MENTOR_PIPELINE_TIMEOUT`、`MENTOR_STATIC_MAX_AGE`、`MENTOR_GZIP_MIN_BYTES`、`MENTOR_APP_VERSION`；
- 非 API 的 404/405/413/500 返回统一 HTML 错误页，带请求编号；API 继续返回 JSON error envelope；
- 所有响应加 `X-Request-ID`、`X-Content-Type-Options`、`X-Frame-Options`、`Referrer-Policy`、`Permissions-Policy`；
- 上传大小由 Flask `MAX_CONTENT_LENGTH` 统一拦截，避免每个接口各写一套；
- 静态资源缓存策略由 `STATIC_MAX_AGE` 控制，默认仍用 ETag 重新校验，方便开发。

## 边界

- 设置抽屉是“本机应用”的配置入口，不引入账号体系；密钥仍只保存在本机 `data/ai_config.json`。
- 处理层中断恢复只处理派生结果，不回滚已经入库的业务数据；写入中断的 `applying` 状态仍建议人工核对后再重试。
- 上传上限默认 25 MB，比原来的 20 MB 略宽，但仍是硬限制；解析器内部的行数上限继续保留。
