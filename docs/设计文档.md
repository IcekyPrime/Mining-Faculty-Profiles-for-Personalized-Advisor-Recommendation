# 上海交通大学导师推荐系统 · 数据挖掘课程大作业设计方案

> 版本 v1.0 · AI3602 Data Mining · 面向保研、考研与进组学生的导师选择系统

## 1. 项目概述

项目目标是构建一个覆盖上海交通大学多学院的**导师推荐系统**。系统爬取全校教师名录，并在此基础上逐位采集研究方向、论文发表、荣誉与课程评价等信息，形成结构化基础数据库；随后以数据挖掘课程所学方法处理与建模，最后通过前端应用让学生按关键词检索导师、按多种指标排序、查看详情，并借由带超链接的研究方向关键词在相关导师之间跳转。

项目遵循「数据层 — 处理层 — 应用层」的三层架构：数据层负责多源数据的采集与集成，处理层承载课程算法，应用层负责交互与可视化。三层解耦，便于分阶段实现与后续迭代。

### 应用场景

- **保研 / 考研学生**：按目标研究方向检索导师，综合学术能力与教学口碑做出选择。
- **本科生进组**：了解某研究领域校内有哪些导师、各自方向与成果，寻找实验室机会。
- **跨学院了解**：从「强化学习」「计算机视觉」等关键词出发，跨学院聚合相关导师。

### 预期成果

- 一个可运行的三层系统，含爬虫、处理管线与 Web 应用。
- 覆盖上海交通大学若干（目标为全部）学院的结构化教师数据库。
- 支持关键词检索、综合排序、详情查看、关键词跳转的完整交互闭环。
- 一份清晰对应课程知识点的设计与成果展示材料。

## 2. 功能设计

### 2.1 数据层：多源采集与集成

数据层从四类来源采集信息，统一汇入基础数据库，并完成清洗、去重与字段对齐。

| 数据源 | 采集方式 | 字段内容 |
|---|---|---|
| 学院官网 / 教师主页平台 | 静态解析（requests + BeautifulSoup） | 姓名、职称、学院、研究方向、教育背景、荣誉、主页链接 |
| 开放学术 API | OpenAlex / DBLP / Semantic Scholar | 论文标题、年份、引用量、合作者、研究主题 |
| 选课社区 API（推荐功能 1） | 官方接口调用 | 教师所授课程的平均评分与评价数量 |
| 传承交大 API（推荐功能 2） | 官方接口调用 | 课程资料、教学相关指标，用于衡量教学质量 |

数据集成环节对多源结果做**实体解析**：同名教师、不同学院页面的同一人物、以及主页与论文库中姓名的中英文差异都需要归并。这里复用课程中的相似项检索思路——对教师姓名与院系组合构造特征，用 MinHash + LSH 找出疑似重复记录，再人工或规则确认。

### 2.2 处理层：数据挖掘

处理层围绕「检索、排序、推荐」三个目标组织算法：

- **研究方向关键词抽取**：对研究方向与论文标题/摘要做中文分词与关键词提取，生成每位教师的「研究方向词袋」。
- **相似检索索引**：用 Shingling + MinHash 生成方向签名，LSH 建桶，支撑近似匹配与相关教师召回。
- **学术影响力排名**：以论文合作/引用关系构建图，PageRank 计算学术影响力，HITS 区分「领域枢纽」与「权威产出」。
- **研究社区发现**：以 Louvain 算法在合作网络或方向相似图上发现研究社群，支撑「相关导师」推荐。
- **研究方向聚类**：用 K-means 将教师研究方向聚为若干主题簇，作为检索的语义分组。
- **方向共现规则**：挖掘频繁项集与关联规则，得到「研究方向 A 常与方向 B 共现」的知识，用于关键词联想。
- **综合评分模型**：融合论文产出、引用影响、荣誉、课程评分与教学质量，输出可解释的「导师能力」综合分。

### 2.3 应用层：检索、排序与跳转

- **检索页**：输入研究方向关键词，返回相关导师列表；支持按「相关度」「学术能力」「教学口碑」等自选排序方式。
- **详情页**：展示导师完整画像（方向、论文、荣誉、课程评分），研究方向关键词带超链接。
- **关键词跳转**：点击详情页中的关键词，跳转到以该关键词筛选出的相关导师列表；跳转逻辑由研究社区与方向共现关系驱动。
- **可视化**：导师能力雷达图、合作网络图、研究方向聚类图。

### 2.4 推荐功能的接入方式

两个推荐功能统一以**「外部评分维度」**的形式接入处理层的综合评分模型，不改变三层架构。选课社区 API 返回课程平均评分，经**指数衰减窗口**对近期评价赋予更高权重后，作为教学维度的输入；传承交大 API 提供课程资料与教学指标，同样归一化后汇入评分。

> **风险与回退**：选课社区与传承交大的 API 并非公开标准接口，端点与鉴权需在实现阶段实测确认。若无法稳定调用，系统保留「仅基于学术数据 + 教师主页荣誉」的评分路径，不影响核心检索与排序功能交付。

## 3. 技术方案

### 3.1 数据爬取方案

静态页面采用 `requests` + `BeautifulSoup` / `lxml` 解析；动态渲染页面（如有）用 `Selenium` 或 `Playwright`。爬虫遵守站点 `robots.txt`，设置请求间隔与重试，并对已抓取 URL 用 **Bloom Filter** 去重。学术数据优先走开放 API（OpenAlex、DBLP）。采集结果落盘为中间缓存（JSON/HTML），再进入清洗流程，支持增量更新。

### 3.2 数据存储方案

主库使用 **SQLite**，按教师、论文、课程、合作关系等关系表组织；图结构（合作网络）以邻接表导出，交由 `networkx` 在内存中做算法计算。研究方向相似索引（LSH 签名）单独持久化，供检索快速加载。

### 3.3 数据挖掘处理方法

| 处理目标 | 方法 | 实现依赖 |
|---|---|---|
| 关键词抽取与向量化 | jieba 分词 + TF-IDF | jieba、scikit-learn |
| 相似检索 | Shingling + MinHash + LSH | 自实现 / datasketch |
| 实体解析（去重） | MinHash + LSH 候选对 | 自实现 |
| 学术影响力 | PageRank、HITS | networkx / 自实现幂迭代 |
| 社区发现 | Louvain（模块度） | python-louvain / networkx |
| 方向聚类 | K-means | scikit-learn |
| 方向共现 | 频繁项集 + 关联规则 | mlxtend / 自实现 Apriori |
| 综合评分 | 多指标加权归一化 | pandas、numpy |

### 3.4 前端实现方案

后端以 **FastAPI** 提供 REST 接口（检索、排序、详情、关键词跳转），前端采用 **Vue 3** 配合 **ECharts** 做可视化。保留「Flask + Jinja + Bootstrap」轻量回退方案。全部代码由 Conda 管理运行环境，环境创建于 `D:\Environment`。
