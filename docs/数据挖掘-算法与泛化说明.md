# 数据挖掘算法与泛化说明

> 适用：`Mining-Faculty-Profiles-for-Personalized-Advisor-Recommendation-副本` v2.7.0  
> 目标：在**不扩充教师/论文数据**的前提下，把项目从“针对当前 773 人写规则”改成
> “换一批文本或换一个学院仍能运行的通用数据挖掘流水线”。

## 1. 整体流水线

```
教师/论文/课程原始表
  → 文本清洗、字段归一化、缺失值标记
  → TF-IDF 关键词 + 相似检索（MinHash/LSH）
  → 合作网络（PageRank/HITS/Louvain）
  → 主题模型（NMF）+ 自动聚类（SVD + K-means + Silhouette）
  → 关联规则（Apriori）
  → 评分 v1 / v2（原始四维 + 改进五维并列）
  → BM25 / 主题混合 / 规则检索
  → NDCG、MAP、P@5 离线评估
```

对应代码：

| 阶段 | 代码 | 输出 |
|---|---|---|
| 文本清洗与分词 | `processing/text_utils.py`、`app/mining.py` | 统一文本、jieba 词序列 |
| 关键词 | `processing/keyword_extract.py` | `processing.keywords` |
| 相似检索 | `processing/similarity_index.py` | `data/exports/similar_pairs.json` |
| 链接分析/社区 | `processing/ranking.py`、`processing/community.py` | `pagerank/hits/community` |
| 主题模型 | `processing/topic_model.py` | `data/exports/topics.json`、`topic_primary/topic_distribution` |
| 聚类 | `processing/clustering.py` | `processing.cluster`、`cluster_meta.json` |
| 关联规则 | `processing/association.py` | `association_rules.json`、`association_meta.json` |
| 检索 | `app/retrieval.py`、`app/mining.py`、`app/api.py` | `sort=bm25/topic` |
| 评估 | `scripts/evaluate_retrieval.py` | `docs/eval/results.md` |

## 2. 关键算法与公式

### 2.1 TF-IDF 关键词

对教师文本 \(d\) 中的词 \(t\)：

\[
\mathrm{tfidf}(t,d)=\mathrm{tf}(t,d)\cdot \left(\log\frac{1+N}{1+\mathrm{df}(t)}+1\right)
\]

- `TfidfVectorizer(min_df=2, max_df=0.85)` 过滤极罕见与极常见词；
- 每篇取 TF-IDF 最高的 12 个词作为 `processing.keywords`；
- 只用研究方向，缺失时才退回简介，避免“上海交通大学”这类履历词进关键词。

主题模型另用小一号的 `max_df=0.70`，避免“人工智能”“机器学习”这类超高频词淹没细分主题。

### 2.2 BM25F

\[
\mathrm{score}(q,d)=\sum_{t\in q}\mathrm{idf}(t)\cdot
\frac{\mathrm{tf}_w(t,d)(k_1+1)}
{\mathrm{tf}_w(t,d)+k_1(1-b+b\cdot \frac{|d|}{\mathrm{avgdl}})}
\]

- 字段权重：姓名 4.0、拼音 2.5、关键词 2.0、方向 2.0、研究所 1.0、职称 1.0；
- `df` 按“文档”去重，不按字段累加；
- 查询别名来自 `data/mining/lexicon.json`，并从语料自动学习“中文（缩写）”；
- 短英文别名按词边界匹配，`html` 不会命中 `ml`。

### 2.3 主题模型 NMF

给定 TF-IDF 矩阵 \(X\)，NMF 求非负矩阵 \(W,H\)：

\[
X \approx W H,\quad W\in\mathbb{R}^{N\times K},\ H\in\mathbb{R}^{K\times M}
\]

- \(W\)：教师-主题权重；行归一化后得到 `topic_distribution`；
- \(H\)：主题-词权重；每主题取前 15 个词，前 3 个词组成 label；
- K 的候选范围随语料规模增长（约 \(\sqrt{N}/3.5\)），再用轮廓系数选择；
- 查询侧把查询词投影到主题词空间，与教师主题分布做余弦相似度：

\[
\mathrm{topic}(q,d)=\frac{\vec{q}_{topic}\cdot \vec{d}_{topic}}
{\|\vec{q}_{topic}\|\|\vec{d}_{topic}\|}
\]

纯主题分是粗粒度画像，应用层不直接用它单独排序。

### 2.4 主题混合检索

在 BM25 已召回集合 \(D_{bm25}\) 上，先做 min-max 归一，再融合：

\[
\mathrm{hybrid}(d)=0.6\cdot \mathrm{norm}(\mathrm{bm25}(d))
+0.4\cdot \mathrm{norm}(\mathrm{topic}(d))
\]

- 只在 BM25 召回集内融合，避免主题模型把完全没有词法依据的档案拉进来；
- `sort=topic` 即该混合排序；topic 分只在 `sort=topic` 时参与召回，
  score/relevance/bm25 等其它排序不再被主题弱相关记录污染。
- 0.4 来自 10 条标注查询上的对比，见第 4 节。

### 2.5 自动聚类

1. TF-IDF 得到高维稀疏矩阵；
2. `TruncatedSVD` 降到最多 50 维，缓解维度诅咒；
3. 在 4–8 个候选 K 上跑 K-means；
4. 用轮廓系数 \(s(i)=\frac{b(i)-a(i)}{\max(a(i),b(i))}\) 选择 K；
5. 输出 `processing.cluster` 和 `cluster_meta.json`。

### 2.6 Apriori 关联规则

事务 = 每位教师命中的研究项集。对规则 \(A\Rightarrow B\)：

\[
\mathrm{support}=\frac{|A\cup B|}{N},\quad
\mathrm{confidence}=\frac{|A\cup B|}{|A|},\quad
\mathrm{lift}=\frac{\mathrm{confidence}}{\mathrm{support}(B)}
\]

- 项集优先从 `data/mining/lexicon.json` 的 `areas` 读取；
- 没有配置时，从当前语料 TF-IDF 高频词自动生成项集；
- `MENTOR_RULE_SUPPORT` 可覆盖最小支持度，适配大小不同的数据集。

### 2.7 图挖掘与相似检索

- **MinHash + LSH**：把关键词集合转为 shingle，100 个哈希签名、20 个 band；
  候选对再用精确 Jaccard \(J(A,B)=|A\cap B|/|A\cup B|\) 过滤；
- **PageRank**：合作网络上的随机游走，`pagerank` 表示合作影响力；
- **HITS**：authority/hub 区分“被合作者引用”和“主动合作”；
- **Louvain**：关键词 Jaccard kNN 相似图上的模块度优化，输出 `community`；
  它是“研究相似社区”，不是共同作者社区。

## 3. 泛化设计

| 设计 | 做法 | 为什么不是“只对当前数据” |
|---|---|---|
| 领域词典外置 | `data/mining/lexicon.json` 的 `aliases` / `areas` | 换学科直接换 JSON，不改 Python |
| 语料自学习缩写 | `learn_acronyms()` 扫描“中文（ML）”模式 | 新数据中出现缩写对即可自动扩展 |
| 自动主题数 | 语料规模 + 轮廓系数 | 小数据不会被强制 8 个主题，大数据不会只有 4 个 |
| 自动聚类 K | SVD + K-means + Silhouette | K 不再写死为 8 |
| 动态关联项集 | 词典优先，缺失时 TF-IDF 高频词 | 没有人工词表也能跑 |
| 通用字段拼接 | `corpus_text()` 只取存在的字段 | 缺 `research_topics`、缺简介时不会崩 |
| 模型结果 JSON 化 | `topics.json` 不保存 sklearn 对象 | 部署端只读 JSON，换数据重跑脚本即可 |

仍然存在的边界：

- 字段语义仍是“教师画像”，不是任意表格零配置；
- 中文分词依赖 jieba 词典，专业新词需要在 `lexicon.json` 的 `areas` 里补充；
- 主题模型需要一定文本量；教师文本过短时会退化为更少的主题；
- 10 条标注查询只能做课程级对比，不能替代正式 benchmark。

## 4. 当前评估

运行：

```powershell
.\.venv\Scripts\python.exe scripts\evaluate_retrieval.py
```

结果（2026-11-26，10 条人工标注查询）：

| 方法 | NDCG@10 | MAP@10 | P@5 |
|---|---:|---:|---:|
| 规则相关度 | 0.954 | 0.925 | 0.920 |
| BM25F | 0.768 | 0.673 | 0.680 |
| 纯主题模型 | 0.097 | 0.050 | 0.080 |
| BM25 + 主题（0.6/0.4） | **0.798** | **0.703** | 0.660 |

解释：

- 纯主题模型只适合“看画像”，不适合单独做排序；它会把同一主题但方向不同的教师排在一起；
- 混合检索保留 BM25 的词法证据，再用主题做重排，NDCG +0.030、MAP +0.030；
- 原始 `score.py` 保持四维权重（论文 0.10 / 引用 0.20 / 荣誉 0.35 / 教学 0.25），
  `score_v2.py` 才是五维分位数 + 缺失感知 + 收缩先验；两者并列展示，不混用。

## 5. 复现命令

```powershell
# 1. 重算主题画像（写入 processing 派生列 + topics.json）
.\.venv\Scripts\python.exe processing\topic_model.py

# 2. 重算自动 K 聚类
.\.venv\Scripts\python.exe processing\clustering.py

# 3. 重算动态项集关联规则
.\.venv\Scripts\python.exe processing\association.py

# 4. 评估
.\.venv\Scripts\python.exe scripts\evaluate_retrieval.py

# 5. 全量测试
.\.venv\Scripts\python.exe -m pytest tests -q
```

可选环境变量：

| 变量 | 默认 | 作用 |
|---|---|---|
| `MENTOR_LEXICON_PATH` | `data/mining/lexicon.json` | 替换领域词典 |
| `MENTOR_TOPIC_K` | 自动 | 固定主题数（调试/课程演示） |
| `MENTOR_CLUSTER_MAX` | 8 | 聚类 K 上限 |
| `MENTOR_RULE_SUPPORT` | 0.02 | Apriori 最小支持度 |
| `MENTOR_TOPICS_JSON` | `data/exports/topics.json` | 主题模型 JSON 路径 |
