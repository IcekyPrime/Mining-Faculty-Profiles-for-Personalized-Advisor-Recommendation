# 荣誉年份丢失修复与数据挖掘功能改进（2026-11-26）

## 1. 问题现象

教师档案页出现大量“年，上海市科技进步一等奖”这类条目，年份为空。检查数据库后确认：

- 不是前端截断，也不是字符编码问题；
- `teachers.honors` 的 JSON 数组里本来就有大量 `"年，..."`；
- 同一位教师的原始主页仍有完整年份，例如 `2025年，上海市科技进步一等奖（排4）`。

因此问题位于**采集/整合后的荣誉清洗环节**，不是页面渲染。

## 2. 根因

两条链路同时存在：

1. **早期整合丢年份**：详情页把年份和奖励正文拆在不同节点，合并脚本只保留了正文，
   留下以“年，”开头的残片。
2. **数据工坊按普通逗号切荣誉**：`split_list` 把 `2025年，上海市科技进步一等奖` 切成
   `2025年` 与 `上海市科技进步一等奖`，重新导入会再次制造同类问题。

## 3. 修复与改进

### 3.1 存量数据修复

使用 `scripts/fix_honors.py`，从原始页面/本地缓存定位奖励正文，取正文前最近的年份补回：

- 发现缺年份教师 **39 人**；
- 修复后仍有异常 **0 人**；
- 教师 625「闵雄阔」的 36 条荣誉恢复为 `2025年，…`、`2024年，…` 等带年份文本；
- 其他教师（曹成喜、方崇荣、黄靖正、霍宏、李德伟等）同步恢复。

执行前备份：

```text
data\db\backup\mentor_before_fix_honors_20261126_225851.db
```

### 3.2 荣誉清洗规则重构

`scripts/fix_honors.py`：

- 识别并过滤 `国内奖励：`、`论文奖励：`、`竞赛奖励：`、`学生奖励：`、`指导学生获奖：`、
  `学术兼职：`、`访问人数：`、`近年来主要科研及教学获奖：` 等分区标题；
- 找不到年份时**不再静默丢弃**，保留正文并追加 `（年份待核）`，便于人工复核；
- 结果按年份倒序排列，最新荣誉在前。

清理前再备份：

```text
data\db\backup\mentor_before_honor_cleanup_20261126_231500.db
```

本轮清理 5 位教师，移除 10 条垃圾条目（9 个分区标题 + 1 个误入邮箱），
荣誉总数从 **3,332** 降到 **3,322**；复核确认被删条目均非真实荣誉。

### 3.3 数据工坊不再切断年份

`app/import_engine.py` 新增 `split_honors()`：

- 荣誉只按分号、竖线、换行做强分隔；
- `2025年，奖项` 中“年份，正文”的逗号保留；
- 一条里出现多个年份时，才按“下一个年份”断句；
- 兼容无年份的普通列表（如 `杰青、优青` 仍拆成两条）；
- 去掉列表编号、首尾标点，并恢复“年份，正文”的可读格式。

示例：

```text
输入：2025年，上海市科技进步一等奖（排4）；2024年，吴文俊人工智能青年科技奖；杰青、优青
输出：["2025年，上海市科技进步一等奖(排4)", "2024年，吴文俊人工智能青年科技奖", "杰青", "优青"]
```

### 3.4 展示层清洗与时间线特征

`app/services.py`：

- `normalize_honors()` 统一过滤分区标题、去重、按年份倒序；
- 没有年份的荣誉排在最后；
- 详情接口新增 `honor_stats`：
  - `count`：荣誉数量；
  - `dated` / `dated_ratio`：有年份数量与比例；
  - `latest_year`：最新年份；
  - `recent_5y`：近五年荣誉数；
  - `categories`：`talent / paper / teaching / competition / student / research_award / other` 分布。

当前全库 3,322 条荣誉中 **1,864 条**能解析出年份，占 **56.1%**。

### 3.5 v2 评分增加荣誉时效

`processing/score_v2.py`：

- 只对**能解析出年份**的荣誉称号做温和衰减：
  `0.75 + 0.25 × 0.5^(age/10)`；
- 10 年半衰期、0.75 下限，2015 年约 0.87、2005 年约 0.82；
- 无年份条目不衰减，避免“资料没写年份”被误判为“荣誉陈旧”；
- `score_parts.honors` 增加 `latest_year`；
- **原始 `processing/score.py` 的固定权重不变**，两套分继续并列展示。

已重跑 `processing/score_v2.py`，更新 `data/exports/scores_v2.json` 与
`data/exports/score_breakdown.json`。
