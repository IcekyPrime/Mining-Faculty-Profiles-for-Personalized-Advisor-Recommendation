## 二、数据：把"未知"和"没有"分开

**问题**：v1.0 的库里 `citation_count` 有 734 人为 0、`paper_count` 有 306 人为 0。
这不是"确实没有引用"，而是 0 填充 —— 综合评分里"引用影响"这一维对 95% 的人恒为 0，
分数实际上只由 h 指数、荣誉、教学三项决定，评审很容易看出不合理。

**做法**（`scripts/merge_authoritative_data.py`，可重复执行）：

1. 以第 40 轮补录产出的 `mentor-整合版.db` 为权威源。合并前逐字段比对确认：
   该库在全部教师字段上是本项目库的严格超集（没有任何"本库有值而整合版无值"的情况）。
2. `honors` 在整合版里混着 JSON 数组与纯文本两种格式，统一规范成 JSON 数组，
   并清掉 `[1] ` 这类编号前缀；编号规则只认方括号/顿号紧邻的形式，
   避免把 `2023 IEEE MTT-S ...`、`2006、2017年上海市...` 的年份误删。
3. `h_index = 0` 且论文数 ≥ 1 的 7 人属于跨来源冲突，按"未知"置 NULL，不参与评分。
4. 论文年份：旧版正则 `(19|20)\d{2}` 用 `findall` 只拿到 `19`/`20` 两个捕获组，
   7634 篇论文年份因此是两位数。合并时按引用串重新抽取 1950–2027 的最后一个合理年份。
5. 论文去重：按 (teacher_id, 规范化标题, 年份) 保留被引最高的一条，去掉 564 条重复。
6. `teachers.teaching_score` 与 `processing.teaching_score` 重复，合并脚本删除该冗余列；
   应用层一直只读 `processing` 的评分字段，无功能影响。

结果：773 人 / 12539 篇论文 / 1663 条课程；引用量覆盖 721 人、论文数 751 人、h 指数 768 人，
其余保持 NULL。合并前后自动备份到 `data/db/backup/`。

> 2026-11-26 后续整合已把论文补到 15,083 篇、引用量覆盖 722 人、论文数覆盖 752 人；
> 本节保留的是当时合并轮次的历史结果，当前口径见 README 与 `docs/2026-11-26-数据整合与网络核验.md`。

## 三、算法：原评分保留，新增缺失感知的 v2

`processing/score.py` **保持原样**（论文 0.10 / 引用 0.20 / 荣誉 0.35 / 教学 0.25 + 5%–95% 截断，继续写 `processing.score`，
不改任何调用方）；改进算法放在新增文件 `processing/score_v2.py`，只写入新增列
`score_v2`、`score_parts`、`score_coverage`，两个分数可并存对照。

v2 的五个维度：论文产出 0.20、引用影响 0.25、学术声誉（h）0.25、荣誉头衔 0.15、教学口碑 0.15。

1. **未知 ≠ 0**：维度值为 NULL 时不参与计算。
2. **权重重新归一**：只用"有数据的维度"求加权平均，再除以可用权重之和。
3. **分位数排名**代替 5%–95% 截断：引用量长尾严重，排名比线性截断更稳健，也更好解释。
4. **收缩先验**：`score = (Σw·pct + 0.3×50) / (Σw + 0.3)`，让"只有一个维度有值"的教师
   不会因为该项排第一就拿到接近满分的分数（例如原来某位只有荣誉数据的教师拿到 94.7 分）。
5. **可解释**：`score_parts` 落库，前端直接展示五维条形图；`score_coverage` 表示可用权重占比，
   详情页显示"数据完整度"。
6. **荣誉时效**：能解析出年份的称号按「0.75 下限 + 10 年半衰期」温和衰减
   （`2015` 年约 0.87、`2005` 年约 0.82），无年份条目不衰减；避免把早年荣誉和资料缺失混为一谈。

v2 分数分布（荣誉时效重算后）：最小 21.3 / P25 41.0 / 中位 52.3 / P75 63.6 / 最大 86.9；
信息充分（覆盖度 ≥ 0.8）722 人，信息不足（< 0.5）11 人，前端会明确标出。
原始 `score` 列仍可排序（前端"综合评分"），新增"改进评分"排序读取 `score_v2`。

## 四、文本：关键词与聚类不再被履历污染

v1.0 的关键词里出现了"影响""产学研""深度""研究成果"，K-means 簇心出现
"上海交通大学""至今""自动化系"。原因是把整段个人简介（含教育背景、任职经历、招生宣传）
和论文标题一起丢进了 TF-IDF。

- 新增 `processing/text_utils.py`：领域词表、扩充停用词（机构名/履历词/论文套话）、
  统一分词口径，供关键词抽取与聚类共用，避免两份词表漂移。
- 关键词抽取：研究方向优先，缺研究方向才退回简介；先用 `strip_career` 在
  "曾获/担任/19xx年"等履历标记处截断，再截到 240 字，避免获奖清单混进主题词。
- 聚类：只用研究方向，不再拼接简介。
- 效果：簇心变成"机器学习/安全/密码/电力/芯片/机器人"这类学科词，
  模块度 0.6896，23 个研究社区。

## 五、工程：向成熟开源项目看齐的几处做法

| 做法 | 参考来源 | 本项目落点 |
|---|---|---|
| 应用工厂（app factory） | Flask 官方 "Application Factories" | `app/__init__.py::create_app()`，测试可传临时库 |
| 蓝图拆分路由 | Flask 官方 Blueprints | `app/api.py`，`/api` 前缀集中注册 |
| 12-factor 配置 | 12-factor app | `app/config.py`，`MENTOR_DB_PATH` 等环境变量覆盖 |
| 请求级连接 | Flask 官方 "Teardown Callbacks" | `app/db.py::get_db()/close_db()` |
| 只读连接 | SQLite URI 文档 | `file:...?mode=ro`，从机制上防止接口写库 |
| WAL 模式 | SQLite "Write-Ahead Logging" | 启动时开启，补录脚本写库时读请求不阻塞 |
| 缓存按数据版本失效 | Flask-Caching / Django cache key 思路 | `lru_cache` 键带 (path, mtime, size) |
| 统一错误响应 | FastAPI / RFC 7807 风格 | `{"error": {"code","message"}}` |
| 结构化日志与耗时 | 常见 Web 服务实践 | `logging` + `X-Response-Time-ms` |
| 测试夹具复制数据库 | pytest 官方 fixture 模式 | `tests/conftest.py`，测试不碰真实数据 |
| Lint + CI 门禁 | ruff / GitHub Actions 模板 | `pyproject.toml` 规则、`.github/workflows/ci.yml` |

架构分层：

```
app/
├─ __init__.py   create_app：配置、日志、蓝图、错误处理、gzip、缓存头、定时器
├─ config.py     默认配置 + 环境变量
├─ db.py         只读连接、请求级连接、WAL、索引自检、文件戳
├─ services.py   检索语料、统计、百分位、相似/合作映射、排序、详情组装
├─ api.py        6 个 GET 接口 + 参数校验 + ApiError
└─ app.py        兼容入口：python -m app.app / python app/app.py
```

## 九、应用外壳与服务加固（2026-11-26 增量，只增不删）

这一轮处理的是“功能都在，但页面切换和边界状态不完整”的问题，没有重排首页三功能区。

### 1. 数据工坊的设置入口

- 设置抽屉从 `index.html` 抽成 `_settings_drawer.html`，首页与 `/workspace` 共用；
- 工坊顶栏增加齿轮按钮，补齐 `aria-haspopup/aria-controls/aria-expanded`；
- 工坊内“数据工坊”导航项显示为“当前页面”，避免自链接；
- 首页仍然可以从设置抽屉进入数据工坊，工坊里不再丢掉设置能力。

### 2. 设置抽屉的可用性

- 打开后聚焦关闭按钮，Tab 在抽屉内循环，Escape 和遮罩可关闭；
- 关闭后焦点回到触发按钮；
- 有未保存修改时关闭二次确认，离开页面前由 `beforeunload` 提醒；
- 保存/测试连接期间禁用按钮并设置 `aria-busy`，避免重复请求；
- API Base 只接受 `http(s)`，启用远程模型必须有 Key，启用联网必须有搜索 Key，
  网页结果数限制 1–10；
- 错误字段加 `is-invalid`，不再只在底部显示一条笼统错误。

### 3. 数据工坊任务

- 预览 token 写入 `?job=`，刷新或复制链接可恢复同一预览；
- 任务状态用徽标显示“预览中/写入中/已入库/失败”；
- 处理层失败时展示具体错误，不再只显示一个灰色步骤；
- 服务启动时把遗留的 `queued/running` 处理层任务标记为 `failed`；
- 创建任务元数据失败时清理已生成的预览行文件。

### 4. 服务配置与 HTTP 边界

- 数据库、AI 配置、导入/备份目录、合作边、相似度、词典、主题文件全部支持环境变量；
- 新增上传上限、处理层超时、静态缓存、gzip 阈值、应用版本配置；
- 非 API 的 404/405/413/500 返回中文 HTML 错误页，API 继续返回 JSON；
- 响应增加 `X-Request-ID`、`X-Response-Time-ms` 与基础安全头；
- 上传大小由 `MAX_CONTENT_LENGTH` 统一拦截，避免接口各自为政。

## 十、仍然存在的限制（没有在本轮解决的）

1. **合作网络覆盖有限**：PageRank/HITS 覆盖 729 人，以原版 arXiv/Crossref 合作边为基线；
   其余教师仍可能因作者缩写/同名无法对齐。
   其余学院论文的引用串只含姓名缩写（`T. Bai`），实体对齐误配风险高，本轮没有贸然扩大。
2. **h 指数大于论文总数 92 人**：两个指标来自不同来源（h 指数含更早/未被收录的论文），
   口径不一致，报告中标注为异常但未强行修正。
3. **论文年份仍有 3180 篇缺失**：引用串里确实没有年份，或格式非常规。
4. **同姓名多条记录 4 组**：无法仅凭姓名判断是否为同一人，保留原样并在相似导师里体现。
5. **关联规则当前只有 5 条**：研究方向文本较短，且项集改由 `data/mining/lexicon.json`
   的 53 个 `areas` 生成，`min_support=0.02` 下频繁项集有限；可用 `MENTOR_RULE_SUPPORT` 调整。
6. **数据采集层未重构**：`crawler/` 仍是一次性脚本，需要登录态与网络，无法纳入 CI。
